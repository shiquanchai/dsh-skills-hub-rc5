# 0.0.8 — 修复 Windows 市场技能安装/卸载失败

## 问题

在 Windows 桌面端从技能市场安装技能时，界面提示 **Failed to publish the skill to disk**；卸载时也可能提示 **Failed to remove the skill directory**。

## 根因

安装流程会把技能文件先写进技能根目录下的隐藏暂存目录，再一次性重命名发布。技能根目录同时被宿主的文件系统技能监听器（chokidar）扫描，Windows 的杀毒/索引服务也会在新文件写入后立即打开它们。

当技能包含较多文件、安装耗时超过监听器的稳定阈值（200ms）时，暂存目录会被扫描；此时目录重命名或删除会因其他句柄尚未释放而返回 `EPERM`。这是 Windows 上目录重命名的瞬时共享冲突，不是权限配置错误，重试几毫秒后即可成功。

复现数据：在同一技能根目录快速写入 40 个文件后立即重命名，30 次中有 6 次 `EPERM`；改为技能根之外暂存 + 退避重试后，20/20 成功。

## 变更

- **暂存目录移出技能根**：改为技能根旁的隐藏目录 `.skills-hub-work`（同一卷，重命名仍是同盘原子操作），宿主的技能监听器不会再扫描到写了一半的技能。父目录不可写时自动回退到技能根内的旧行为。
- **瞬时错误退避重试**：`EPERM` / `EACCES` / `EBUSY` 最多重试 8 次（25ms 起指数退避，总计约 3 秒），非瞬时错误仍然立即失败。
- **卸载同样加固**：目标先重命名到工作目录中的回收目录，再删除；重命名与删除都带重试。
- 发布失败信息附带系统错误码（如 `(EPERM)`），便于后续诊断；不泄露任何绝对路径。
- 新增 `src/market/fs-retry.ts` 与对应单元测试，覆盖重试、非瞬时错误、无错误码和重试耗尽。
- 版本提升到 `0.0.8`。

## 验证

- `tsc` 宿主 + 客户端两套配置通过。
- 回归测试 111 项：110 通过；唯一失败仍是 Windows 无符号链接权限的既有环境用例（`EPERM`，测试夹具无法创建）。
- 端到端：通过编译后的安装服务安装/卸载 `planning-with-files`（36 个文件）和 `wps-office`（9 个文件）成功，技能根无残留，工作目录自动清理。
- 快速多文件压测：修复前 30 次中 6 次失败；修复后 20/20 成功。
