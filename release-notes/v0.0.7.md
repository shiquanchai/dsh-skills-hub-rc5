# 0.0.7 — 适配 DeepSeek Harness 0.2.1-rc.5

## 问题

0.0.6 的 peer 依赖只声明到 `0.2.1-rc.3`。桌面端升级到 **0.2.1-rc.5** 后，宿主启动时的兼容性检查会拒绝加载插件，并提示版本不兼容；npm 安装同样会被 `incompatible-version` 拒绝。

## 变更

- 兼容策略新增 `0.2.1-rc.5`（GitHub 标签 `dsh-v0.2.1-rc.5`，提交 `b830ec950faba0a46dda564be3e2d854afed94f1`），并将其设为推荐宿主。
- 全部 `@deepseek-ai/dsh-*` 开发依赖统一到 `0.2.1-rc.5` 同一队列。
- peer 依赖由兼容策略生成：`0.2.1-rc.1 || 0.2.1-rc.2 || 0.2.1-rc.3 || 0.2.1-rc.5`。
- 重新生成 `lib/`，插件版本提升到 `0.0.7`。

## 兼容性依据

逐一比对官方 npm 上 rc.3 与 rc.5 的 `dsh-host-webserver`、`dsh-client-connection`、`dsh-client-locale`、`dsh-client-ui-layout`、`dsh-client-ui-slots`、`dsh-client-ui-primitives`、`dsh-client-ui-sidebar`、`dsh-client-ui-renderer`、`dsh-skill`、`dsh-skill-filesystem`、`dsh-home-paths`、`dsh-fs`、`dsh-scope` 等包：

- 除 `package.json` 中的版本号外，类型声明与运行时实现无差异；
- 唯一的运行时代码差异是侧栏构建版本横幅（`0.2.1-rc.3-…` → `0.2.1-rc.5-…`）；
- 桌面端 `app.asar` 内的 rc.5 运行时与 npm rc.5 包一致（CSS 构建哈希差异除外）。

因此 0.0.6 的运行时代码本身适用于 rc.5，拒绝加载仅来自版本门槛；本版本更新门槛并重新验证。原有 rc.1 / rc.2 / rc.3 支持继续保留。

## 验证

- 以 rc.5 队列执行 `tsc`（宿主与浏览器两套配置）通过。
- 回归测试通过；唯一跳过的是 Windows 无符号链接权限时的 `EPERM` 环境用例。
- 在隔离 `DSH_HOME` 与独立 profile 中，用 rc.5 宿主安装本地 tarball 并启动 Web 宿主：插件行成功激活，`/api/skills-hub/status` 返回 200，客户端 `lib/client.js` 由宿主模块加载器提供且无启动错误。

## 安装

0.0.7 发布到 npm 前，请使用本地构建的 `nanmicoder-dsh-skills-hub-0.0.7.tgz`：

```text
dsh plugin --profile desktop add <tarball 的绝对路径>
```

安装前完全退出桌面端，安装后重新打开。
